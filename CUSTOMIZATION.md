# Адаптация экземпляра под кофейню

Один экземпляр Coffie Bot обслуживает одну организацию. Несколько `venues` описывают её
заведения/бренды, а `locations` — физические точки и места выдачи, не независимых арендаторов.
Для другого заказчика создайте
новый репозиторий, bot token, базу, volumes и deployment — не добавляйте `tenant_id`.

## 1. Создайте отдельный экземпляр

Скопируйте шаблон в новый приватный репозиторий. До первого запуска выберите уникальные:

- `COMPOSE_PROJECT_NAME`;
- `POSTGRES_VOLUME_NAME`;
- `MEDIA_VOLUME_NAME`;
- имена Docker images.

Не подключайте новый экземпляр к volumes, `.env` или базе другого заказчика. Не переносите
историю клиентов через demo seed.

## 2. Создайте Telegram-бота

Через официальный BotFather создайте отдельного бота и сохраните:

- token в `BOT_TOKEN`;
- username без `@` в `TELEGRAM_BOT_USERNAME`;
- публичный HTTPS URL Mini App в `TELEGRAM_WEBAPP_URL`.

Не вставляйте token в исходники, seed, Compose или переписку. До появления production-домена
используйте отдельного тестового бота.

## 3. Подготовьте окружение

Скопируйте `.env.example` в `.env` и замените все placeholder-значения. Обязательно задайте:

- длинный случайный `POSTGRES_PASSWORD`;
- независимый `SESSION_TOKEN_PEPPER`;
- Telegram-параметры;
- единственный разрешённый production origin в `CORS_ORIGINS`;
- HTTPS URL в `TELEGRAM_WEBAPP_URL`.

В production `DEV_AUTH_ENABLED` должен быть `false`. `compose.prod.yaml` устанавливает это
значение принудительно, а backend дополнительно отказывается запускаться с bypass.

## 4. Измените бренд

До первого импорта отредактируйте раздел `brand` в `configs/demo-seed.json`:

- название и короткое название;
- приветственный текст и название внутренней валюты;
- основной, дополнительный и фоновый цвета;
- ссылки на media после загрузки изображений.

Не добавляйте название, цвета или тексты клиента в Python/TypeScript. После первичного seed
настройки, доступные администратору, меняются через API/админку и хранятся в PostgreSQL.

## 5. Подготовьте изображения

Исходные логотипы и фотографии храните вне Git. После запуска загрузите их через защищённый
admin media endpoint. Допускаются только JPEG, PNG и WebP до настроенного лимита; SVG и HTML
не используются. Backend создаёт storage key и сохраняет файл в media volume.

Проверьте отдельно:

- логотип на светлой и тёмной теме;
- hero/card image на узком экране;
- изображения меню и акций;
- отсутствие персональных данных в metadata исходного файла.

## 6. Подтвердите правила лояльности

Demo-настройки нельзя считать согласованными с заказчиком. Совместно с владельцем заполните
решения из `docs/PRODUCT_DECISIONS.md`, особенно:

- формулу начисления, округление и лимиты;
- денежную ценность одного балла и максимальный процент списания;
- правила посещений, business-day boundary и timezone;
- что считается оплаченной позицией для штампа;
- награды, сроки действия и reversal policy;
- нужен ли approval крупной операции;
- сроки хранения персональных данных, audit и backups.

Все суммы в seed/API задаются в копейках. Например, `10000` означает 100 рублей.

## 7. Заполните контент и контакты

Замените в seed демонстрационные:

- телефон, email, сайт, privacy/support URL;
- адрес, график и timezone каждой точки;
- категории и позиции меню;
- акции;
- reward templates.

Удалите неактуальные demo-записи. Не добавляйте реальные платёжные реквизиты для чаевых:
сотрудник создаёт собственный профиль, а администратор модерирует его перед публикацией.

## 8. Запустите миграции и создайте владельца

После настройки `.env`:

```bash
make up
make migrate
make create-owner OWNER_TELEGRAM_ID=123456789 OWNER_NAME="Имя владельца"
```

Без Make:

```bash
docker compose --env-file .env up --detach --build
docker compose --env-file .env run --rm migrate
docker compose --env-file .env run --rm backend \
  python -m app.cli create-owner --telegram-id 123456789 --display-name "Имя владельца"
```

Не назначайте owner через изменение frontend state или прямое редактирование браузера.
После входа проверьте роль через backend.

## 9. Импортируйте стартовые данные

После создания владельца импортируйте конфигурацию и demo-контент:

```bash
make seed
```

Без Make:

```bash
docker compose --env-file .env run --rm backend \
  python -m app.cli seed --file /app/configs/demo-seed.json
```

Раздел `development_only` содержит синтетического demo-сотрудника. Importer обязан
пропускать его вне `APP_ENV=development`; перед production всё равно удалите этот раздел или
проверьте, что такой пользователь не создан.

Создайте отдельные учётные записи staff/admin через интерфейс после первичного входа owner.

## 10. Проверьте экземпляр

До публикации выполните автоматические проверки:

```bash
make lint
make format-check
make typecheck
make test
```

Затем пройдите `docs/MANUAL_TEST_PLAN.md` с отдельными customer, staff, admin и owner.
Обязательно проверьте подпись Telegram init data, старый QR после reissue, повторный
idempotency key, конкурентное списание, права и восстановление backup.

## 11. Разверните и передайте

Развёртывание описано в `DEPLOYMENT.md`. После получения HTTPS-домена обновите
`TELEGRAM_WEBAPP_URL`, разрешённый origin и кнопку Mini App в BotFather. Зафиксируйте для
заказчика:

- владельца Telegram-бота и домена;
- расположение `.env` и процедуру ротации секретов;
- имена volumes и каталог backups;
- версию/commit deployment;
- порядок обновления и ответственного за backup rehearsal.

Перед передачей удалите тестовых пользователей, рассылки, feedback и media, но не удаляйте
боевой immutable audit/operation journal.
